# PROJECT: Toram Online full client-data reverse

## Goal

One folder holding every piece of game data recoverable from the client, from the first cached master version to the latest,
in two forms: raw decoded (`data/`) and readable (`readable/`), plus the code layer (`code/`) and the tooling to rebuild it.

## Scope and rules

- Offline static analysis only. Never run, attach to, or modify the game. Never touch anti-cheat (`libxigncode.so`, `files/xigncode/`, XIGNCODE appsign on the PC `GameAssembly.dll`).
- The Android `libil2cpp.so` is not packed (exec segment entropy 6.6) and may be analysed. If any binary turns out to be protection-packed, stop.
- Network use: only public CDN asset files (`https://toram-jp.akamaized.net/resources/android/release{A..D}/`), no login, no game server, no account data.
- Only game-system data: items, skills, quests, monsters, formulas, text. Nothing that helps cheating.
- Human-readable output goes in `readable/`, never mixed into `data/decoded/`.
- Docs, comments and commit messages in English.

## Data model in one page

- Bundles are UnityFS. Cache dir name = 24 zeros + version as LE hex; the last 8 hex chars are the XOR key.
- Outer TextAsset decode: `p[j] = c[j] ^ c[j-4] ^ key_le[j % 4]` (`c[-4..-1] = 0`); the trailing `len % 4` bytes are plain (`tools/s1_extract_all.py`, `readable/csharp/ToramDecoder.cs`).
- FieldScript bundles nest: outer TextAsset -> decode -> inner UnityFS. **Inner assets are plain** (decoding them again garbles them).
- Master tables (`BynaryData`, 38 tables) and text tables (`GameScene_<lang>`, `Quest_*`, `Mission_*`, `sc_*`) formats are documented in `readable/NOTES_original.md`; the text formats are implemented generically in `tools/s5_text_readable.py`.
- Languages on the CDN: th, us, jp, kr, cnt, idn.

## Program (`toramre`, 2026-10-04)

`python -m toramre <cmd>` (or `pip install -e .` at the repo root). Offline; the only network use stays the public CDN (`toramre/brain/guard.py` enforces the scope rules in code: anti-cheat paths, packed/encrypted-looking data and non-CDN hosts raise `Boundary` and stop the run).
- `watch`: tags changes between consecutive kept versions (NEW / REMOVED / CHANGED / TEXT_CHANGED / LAYOUT_BROKEN / BINARY_CHANGED), `CHANGES.md` + `changes.json`, exit code via `--fail-on`. With a learned schema the diff is record- and field-level (ids added/changed, field names).
- `ui`: self-contained dashboard (alerts, table x version change matrix, versions).
- `stage`, `versions`: tools/s1..s6 in order; kept versions per bundle.
- `fetch catalog|plan|get|status|verify` (`toramre/net/`): version tables of channels A-F (changes per channel -> `state/cdn_changes.json`, shown by `watch` as `cdn/<ch>` events), work list by category (`--only data,text,script,model,audio,field`) / `--match REGEX` / delta against `state/fetch_manifest.json`, parallel polite download (`--jobs`, `--rate` token bucket, retries with backoff + jitter, `Retry-After`), resume from `.part` with HTTP Range, MD5 check against the CDN ETag (`"<md5>:<timestamp>"`, observed), `UnityFS` magic + Content-Length check, fsync + atomic rename, `--revalidate` (If-None-Match, 304 = keep), disk-space check, `--then extract,watch`. Output is the Unity-cache layout `cache.py` reads (`--dest` / env `TORAM_CDN_CACHE`, default `<repo>/cdn_cache`, git-ignored; add it to `TORAM_CACHE`). `scripts/cdn_fetch.py` and `tools/s2_cdn_catalog.py` are wrappers. Catalog size field = ~10.4 KB units (Inferred from Content-Length); channel A total estimate ~2.6 GB (model 1.1, field 0.76, audio 0.6, text 0.05 GB).
- `fetch update` / `fetch poll --interval MIN [--once]` (`toramre/net/update.py`): refresh the version tables, fetch only the bundles whose version changed since the last check (default `--only data,text,script`), `--then extract,watch`. A skill re-balance is caught only where it lives in data (SkillMaster in BynaryData, texts in Localize); multipliers / formulas are in `libil2cpp.so` (APK, not on the CDN). Also on `fetch get`: `--force` (download again), `--max-mbps` (speed cap), data -> text -> script -> media order, Ctrl+C keeps finished files and resumes the rest next run.
- `fetch export` (`toramre/assets/`, needs `pip install UnityPy`): every cached bundle -> `<out>/<category>/<bundle>/`: TextAssets decoded with the cache-dir key (inner UnityFS bundles walked, their assets plain), Toram's own model format -> OBJ/MTL/PNG + preview (`toramre/assets/toram_model.py`, moved from `scripts/export_models.py`, which now imports it), Texture2D/Sprite -> PNG, AudioClip -> samples, Mesh -> OBJ, other TextAssets -> `.dec`. Filters `--only`, `--match`, `--types model,texture,audio,mesh,text`; `.export.json` per bundle makes reruns incremental; one bad object is logged, never stops the bundle; `--jobs N` worker processes.
- `brain status|frontier|solve|show`: the chain engine. Frontier = tables that are variable width, only heuristically framed, or whose learned schema stopped fitting. Strategies: code-hint (table name -> owner class -> constructor signature -> element class; enum widths and array count widths enumerated), anchor-fit (record starts from a growing id, record lengths explained by a count, a tag byte (tagged union), tag + count, or two counts), small-search (short grammars for small files). A result is learned only when it fits every distinct version to the last byte, no byte-shuffled copy fits (null test), and it explains many records; otherwise the table stays open with the candidates and the next link (owner classes, their constructors). Strategy success counts (`kb/stats.json`) order the next run.

## Game update runbook (recorded 2026-10-02; tooling built the same day, NOT yet exercised on a real update: only the unchanged-binary path was run)

Driver: `scripts/update_game.py` (`status`, `baseline`, `install --so --meta`, `plan`, `rebuild`); core: `scripts/il2.py`, `fingerprint.py`, `build_factory_maps.py`; overview in `scripts/README.md`. Baseline fingerprints of build `20e5b318` (762 units) are stored in `<work>/state/fp_baseline.json`.

Goal: when the game updates, skip everything that is provably unchanged and go straight to the newest data. Never re-decode what a cheap check shows is identical.

1. **Encryption check (minutes).** Decode one new bundle with the known rule (cache dir name = 24 zeros + version LE hex, last 8 hex chars = XOR key, `p[j] = c[j] ^ c[j-4] ^ key_le[j % 4]`, FieldScript nests twice) and run the exact-EOF master parsers on it. If every parser consumes its file to the last byte, the data layer is unchanged: decode only versions newer than the newest in `readable/masters/_history.csv` (hash per table; `same` rows are skipped) and refresh the exports. If a parser fails, that table's layout changed: fix that parser only.
2. **Binary check.** Pull the new `libil2cpp.so` + `global-metadata.dat` from the phone (Android only; PC build is XIGNCODE-packed and out of scope), compare the SHA-256 with the stored one. Identical = skip steps 3-4. Different = rerun Il2CppDumper (`dump.cs`, `script.json`) and continue.
3. **Per-function fingerprint (the shortcut).** Key every decoded unit (skill action class, `*Buf` class, mastery class, GemCart buff class, each stat/engine function) by *name*, never RVA, and store a hash of its machine code with relative branch/`bl` targets normalised to callee names. Re-decode only units whose hash changed, whose callees' names changed, or that are new; copy the stored recipe for the rest. A game update that touches a handful of skills should re-run a handful of classes, not all 398 actions + 130 registlet buffs.
4. **Regenerate the derived layers** only for changed units: `build_reference.py --all` and the render chain from `skills/damage` (PROJECT.md "Working conventions"), then `build_damage_type.py`, `registlet_inputs.py` + `build_registlet.py`. Each hand-kept table must assert its evidence (`DYN` already asserts the getter text); a failed assert means "review this entry", not "ignore".
5. **Diff report.** Compare old vs new recipes (`regress_skills.py` pattern) and write what changed (skills, registlets, masters) into `NOTES.md`; correct stale docs in the same run (completion rule 8).

## Hard limits (proven not in the client)

Only these are server-side, each with evidence (a network op or a server-fed manager value): shop catalogs, drop rates, quest rewards and EXP, raid level cap (`FunctionLimitManager` value 15), skill cooldown values, ailment/drop rolls, who cooked what.

Crafting skills (Smith/Alchemy) are not purely server-side either: the client computes their success rate / limits (`SmithGrant.getSuccessSkillRate`, `SyntheticEquip.getRate`, `ProficiencyManager.getBlackSmithLimitIncreaseBySkill`), shown on the tree pages.

Skill multipliers, flat damage, MP cost, range, cast-time modifiers and buff values are NOT server-side: they are set in the Android `libil2cpp.so` action/buff classes and are recovered in `skills/damage/`. An older version of this file said otherwise; that claim is wrong. Never stop at "server-only" without naming the exact network op / manager that supplies the value.

## Completion rules (binding for every extraction task)

The recurring failure is stopping at "decoded what the first pass reached" while known links stay unfollowed. The rules below exist to end that. A task is done only when all of them hold.

1. **Enumerate, don't sample.** Work from the full master list (e.g. all 577 tree skills, all `*Buf` classes, all 398 action classes), never from the examples the user mentioned. Finish with a coverage table: done / total / residual, before and after.
2. **Unresolved marker = open TODO, not a result.** Any `?`, `~`-inferred term, `truncated`, a buff with `hooks` but no params, "not decoded", a method with 0 decoded items, or a symbolic value that could be evaluated is unfinished work. Chase it: callee class, base class, `SkillFactory`/`SkillBufferManager` jump tables, enum tables (`SkillBufferId`, `BonusType`, `MasteryId`), master data, then in-game text.
3. **Follow every link in both directions.**
   - Text -> code: each level note (`Lv12 ...`, `Lv13 ...`) and each named effect in a description (mark, stack, invulnerability, extra hit, proc chance) must map to a decoded field/class, or be listed as "unmapped note" with the next step.
   - Code -> owner: enumerate classes from the class list, not only from the skill side. A `*Buf`/`*Action` class no skill constructs directly is created by a manager (songs, dances, pursuit hits, gem-cart buffs, mastery-driven buffs). Run an orphan pass and attach each to its skill by name/id.
   - Value -> consumer: a buff `GetParam(id)` value or a field is only understood once the consumer that reads it (damage engine, `NormalAttackAction`, monster hook, UI) is named.
4. **Caps are not answers.** Path/instruction caps (80 paths / 5000 ins / 3 loop iterations) hide data. Re-run every `truncated` method with raised caps before reporting it as a limit.
5. **Never lose part of a value in the docs.** A renderer must show every recovered field (constructor fields, `Damaged` hooks, `GetParam`, `Updata`), not only one hook. A page that displays `damageCut=0` while the ctor sets 1 is a bug; fix the renderer and regenerate.
6. **One pass to the end.** Do not stop between sub-steps to ask. Keep going until every residual is one of: (a) proven external (cite the op), (b) needs a specific user action (adb pull, in-game check) stated once with the exact ask, or (c) listed in the backlog with the reason. "Would you like me to continue?" is not an allowed ending.
7. **Report numbers, not narrative.** Final message: coverage table, what changed, residual list with reason class, files written. Label each claim `Code` / `In-game` / `Inferred`.
8. **Fix the record in the same run.** When a new finding contradicts an earlier note or doc, correct it there (NOTES, PROJECT, tree pages, README) and say so. Update the backlog and the stale "Hard limits"/caveat lines before ending.

## Working conventions

- Every claim in `readable/NOTES_original.md` carries its evidence; keep the label `Code` / `In-game` / `Inferred`.
- A parser is accepted only when it consumes the file to the exact last byte.
- Run scripts from `D:\toram reverse data\scripts` (`cache.py` merges the PC cache, the phone cache and the CDN cache; newest mtime wins).
- Skill pipeline: `run_skills.py` (per-skill) + `run_orphan_bufs.py` (buff classes no skill constructs) + `skill_consumers.py` -> `run_consumers.py` -> `build_reference.py --all` (the flag is required, without it nothing is written) -> `render_docs.py` -> `finalize_docs.py` -> `build_coverage.py` -> `render_details.py` (skill detail pages; needs `coverage.csv`) -> `render_explained_th.py` (Thai pages, fully generated) -> `render_calc_th.py` (numeric per-hit / per-stack blocks inside `explained_th/`, between `calc:begin`/`calc:end` markers; idempotent, hand-written Thai text outside the markers is kept). Working tree `D:\toram_re`; outputs `skills/damage/`. Then copy `skills/` over `TORAM ONLINE BIGDATA/readable/skills/` (the BIGDATA copy is a snapshot, not regenerated by the scripts).
