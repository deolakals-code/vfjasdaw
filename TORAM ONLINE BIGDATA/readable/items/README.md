## ItemMaster record (37 bytes, all named) — `ItemDBData.CreateItemData` (0x21309D4), label `Code`

`<4i BB hhh BBB h i i>` = Id, SortId, TypeId, Price, MaterialLv, MaterialId, Process, Stack, Function, Stable, Range, SlotMax, Potential, Model, Flag.

| items.csv column | field | notes |
|---|---|---|
| `price` | Price | role (buy/sell) not named in the client |
| `processable`, `material_type`, `material_points` | MaterialLv, MaterialId, Process | MaterialId indexes `ShopUtil.GetLocalizedMaterialName` (0 Metal, 1 Cloth, 2 Beast, 3 Wood, 4 Medicine, 5 Mana); Process = points gained when processed (`Inferred` from data: boxes 100/200, "Metal Point" items) |
| `base_atk_def` | Function | weapon ATK / armor DEF base; also ninko for ninjutsu books (`GetNinko`) |
| `stability`, `range`, `slot_max`, `potential` | Stable, Range, SlotMax, Potential | |
| `avatar_category`, `avatar_category_name` | (Range << 8) \| SlotMax | `ItemDBData.AvatarCategory`, types 25-27 only; names from `AvatarEquip_th` |
| `icon_or_model_id` | Model (int32) | was read as uint16 before: 79 boxes/crystas had a truncated id |
| `flag`, `flags` | Flag | `ItemFlag` enum; `auto_potion` = bit 256 |

Old column `raw_12_36` is gone: no byte is undecoded any more.

## Use status

| Column | Meaning | Evidence |
|---|---|---|
| `can_use` | bag "Use" button exists: type 0, 1, 2, 5, 30, 50 | `ItemDBData.CheckUseItem` 0x2130EB4 = `UIItemListManager.CheckUseItem` 0x1E5E7B4; called by `UIItemBagManager.ItemList/OpenButtonList/ChangeButtonCommand/CallBackUseItem`. `Code` |
| `use_kind` | heal / consume / box / unlock / unique / warp / skill_book | warp = type 2 and first property 244 (`ItemData.IsWarpItem` 0x21307F0); skill_book = first property 246 (`OnUseItem` opens the skill-book popup). `Code` |
| `use_note` | runtime refusals | warp items refused in Guild Raid (room 29) and Score Attack (room 40) rooms; skill book refused when already learned (`ItemBagPanelUseSkillBookFailureMes`). `Code` |
| `can_equip` | types 7-27 | `ItemDBData.CheckEquipItem` 0x2130E44. `Code` |
| `use_channel` | bag / equip / orb_panel (inferred) / none | orb-shop goods (types 52-54, 100-103, 200) are server-fed `OrbItemData` consumed through the orb panel; the client has no per-type list, so this is `Inferred` |
| `unknown` | no ItemMaster record (the 6 text-only ids) | type cannot be known |

The tooltip line `[นำไปใช้ได้]` is narrower (types 1 and 2 only, `UIItemProperty.ItemPropertys` 0x1B233AC); boxes, unlocks and unique items are usable without that line. Whether a given use succeeds (level, HP full, cooldown, server checks) is decided at runtime/server side; the shared item cooldown base constant is `BaseItemDelay = 10` s in the player class (`Inferred` to be the shared one).

## RecipeMaster (`item_recipes.csv`) — `RecipeDBData` (dump.cs 8521), `Code`

Header `<i RecipeId><B Type><h ReleaseLv><i Price><h Difficulty><i CreateId><h CreateVal><B Category>`, then `<I n>` and n x `<B RecipeNo><B Lv><i Id><h Val>`. `Lv 0` = item id x Val, `Lv 1` = material point type (MaterialId index) with Val points. Type Recreate (330 rows): `CreateId` is not an item id (317 not in ItemMaster), so `create_name` is blank there.
Earlier notes that read the material as `<H Lv><I id>` and called `Lv 1` rows "id=0 no material" were wrong; the collect-slot chain (type 3) is unaffected (item ids only).
